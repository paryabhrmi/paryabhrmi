## What I Focus On

- **Design Systems With Governance, Not Just Components**
  Component libraries built on variables, tokens, auto layout and variants, with
  the governance guidelines that keep them from drifting six months later — and
  documentation an engineer can implement from directly.

- **Design-to-Code Handoff and Delivery Quality**
  Owning the path from design file to shipped component: naming, theming,
  handoff consistency, review cadence, and specs that don't need interpretation.
  The measure of a handoff is whether the team stops needing you.

- **Complex, Multi-Role SaaS and Enterprise Flows**
  Dashboards, admin panels, ERP surfaces and role-based workflows where several
  audiences work against one system and each needs a different view of it.

- **AI-Native Product Design**
  Conversational interfaces, AI-assisted workflows, and prompt-based prototyping.
  Designing around what the model gets wrong as much as what it gets right — and
  building the thing rather than specifying it.

- **Product Discovery That Ends in a Decision**
  JTBD, user interviews, journey mapping, heuristic evaluation and A/B testing,
  run to narrow a noisy backlog to the few problems worth building.

- **Research Ops and Behavioural Analytics**
  Standing up research pipelines from zero on Clarity, Mixpanel, Dovetail and
  Amplitude, so decisions get validated against evidence instead of opinion.

- **Interaction, Motion and Accessibility**
  Rive-based interaction patterns shipped to real runtimes, with WCAG 2.2
  conformance, keyboard paths, focus states and reduced-motion treated as part of
  the definition of done.

- **0→1 Product Architecture**
  Schema-driven, modular systems designed once and deployed across industries
  without rebuilding the core flows.
